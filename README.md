# Magisk (e8915d9d) (31000-41)

> su: remove obsolete access and reauth settings<br>With reactive su request prompts removed and superuser permissions<br>granted explicitly ahead of time in the app, the legacy 4-way superuser<br>access mode (Disabled, Apps only, ADB only, Apps & ADB) and pre-O<br>reauthentication after upgrade settings are no longer applicable.<br>ADB shell (com.android.shell) is now an explicit policy entry managed<br>directly in the Superuser tab, making global access filters redundant<br>and prone to conflicting state. Furthermore, revoking policy on package<br>upgrade without reactive prompting silently breaks root for upgraded<br>apps.<br>- Remove RootAccess enum and root_access checks from magiskd.<br>- Remove su access mode and reauthenticate settings from Manager app.<br>- Drop ACTION_PACKAGE_REPLACED from Receiver and manifests.<br>- Purge obsolete string resources across all translations.<br>Assisted-by: Gemini 3.8 Flash

> su: do not notify app when UID has no policy<br>With reactive su prompting removed, root requests from UIDs without<br>an existing policy in the database are rejected immediately. Previously,<br>RootSettings defaulted log and notify to true, causing the daemon to<br>notify the manager app whenever an unconfigured UID attempted to run<br>su.<br>Derive Default for RootSettings so that policy defaults to Deny with<br>log and notify initialized to false, preventing unwanted notifications<br>to the app when no database policy exists. Also simplify SuInfo::allow<br>and SuInfo::deny to leverage Default.<br>Assisted-by: Gemini 3.8 Flash
